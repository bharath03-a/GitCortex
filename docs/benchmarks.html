08 · What didn't pass, bugs caught, and limits

Real bugs this benchmark round caught and fixed before v0.8.0

  • find_callers cross-file diversity (PR #146): on dense hubs like django/db/models/query.py (QuerySet.filter), a single file could fill the entire caller budget and hide cross-file callers. Stratified file-diverse ranking brought the big-repo deterministic gate from 9/10 to 10/10.
  • Incremental hook performance & KuzuDB dense-hub crash (PR #147): editing a hub file with 15,217 incoming edges hit a KuzuDB 0.11.3 DETACH DELETE assertion crash/hang and O(N×M) Cypher name joins. Updating surviving nodes in place, bounding batch lookups by primary key, and threading uncommitted Imports in memory cut ripgrep hooks from 4,170 ms → 423 ms, tokio from >60 s → 821 ms, and eliminated the django crash/hang (6.9 s).
  • Full-index bulk reconciliation (PR #145): resolving initial full-index edges in Rust memory and loading via KuzuDB COPY FROM brought django cold indexing down to 5.3 s and nextjs (120k nodes) to 10.7 s.

Remaining known trade-offs (not hidden):

  • Plain lexical search stays near grep parity on Codex (−3.8% uncached, +9.8% total tokens); GitCortex's clear token wins are on relationship queries (subgraph, impact, refactor, callers).
  • moby cold indexing: GitCortex indexes vendored Go directories by default (269k nodes, 23.8 s, 298 MiB), whereas CodeGraph skips vendor dirs (36.8k nodes, 6.7 s, 110 MiB).
  • Unbudgeted adoption overhead: when unconstrained, agents equipped with the guide ran 55 CLI calls across 16 tasks (improving accuracy to 16/16 at higher total token usage).
  • Static analysis scope: dynamic dispatch, reflection, and generated code can be missed; risk labels are investigation signals, not a guarantee of safe changes.
