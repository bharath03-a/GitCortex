Live coding workflow

Edit, query, switch branches, recover — without guessing whether the graph is stale.

Static graphs only stay trustworthy when updates are fast, branches stay isolated, and degraded states say so explicitly instead of returning an empty caller list. Step through the four moments that matter in a real coding session.

Supported update paths: git hooks (post-commit, post-merge, post-rewrite, post-checkout), manual refresh (gcx hook / gcx index), and optional file watching with persistent dirty-state tracking.
Complementary workflow: use graph evidence to map callers and cross-file impact quickly, then inspect the cited lines in source and run your test suite before shipping. Static analysis can miss dynamic dispatch or generated code.
No unbounded store growth: gcx storage list, prune, gc, and compact preview everything before deleting, and safely drop stale branch tables and compact KuzuDB files back to single-branch size.
Honest failure modes: missing, stale, or degraded indexes return explicit readiness metadata rather than pretending a symbol has zero callers. Run gcx doctor or gcx status --json at any time to verify hooks, store health, and editor wiring.
How it works

A typed graph, updated incrementally from your git history.

Four git hooks (post-commit, post-merge, post-rewrite, post-checkout) diff from the last indexed SHA rather than HEAD~1, so rebases, amends, and branch switches keep each branch's table synchronized — and manual gcx hook or gcx index recovers immediately whenever hooks are skipped.

The explorer

Same schema, painted as a graph you can walk.

gcx viz serves the graph as a local web app: an atlas for orientation across the whole repository, and an investigation canvas for tracing one symbol's exact neighbourhood. Both run against your own indexed repository. These are real captures of GitCortex indexing itself.

Design decisions

Local analysis, bounded evidence, honest operational limits.

Local analysis

Embedded Rust + KuzuDB

Parsing, graph storage, and MCP/CLI queries run locally on your machine with no GitCortex cloud backend or LLM calls. Setup downloads packages/binaries as usual, and your AI assistant's own model requests follow its configured network path.

Incremental

Fast hooks + explicit readiness

Only changed files are re-parsed and reconciled from the last indexed SHA. Every response surfaces index.state (ready, stale, missing, or degraded) with recovery guidance.

Branch-aware

Isolated & reclaimable

Each branch gets its own isolated storage namespace and supports structural branch_diff. Dry-run-first gcx storage gc and compact reclaim disk from deleted branches.

Complementary

Graph + source + tests

gcx serve (MCP) and gcx query (CLI) accelerate caller, impact, and neighbourhood lookup while working alongside ordinary grep, file reads, and your test suite.

Capabilities

Parsing, progressive search, storage lifecycle, and visualization.

Multi-language AST parsing

A tree-sitter backend provides one structural extraction pipeline across every supported language: definitions, calls, imports, type usages, and Markdown references.

RustGoPythonTypeScriptJavaMarkdown

Progressive deterministic lexical search

Ranked lexical search over symbol names and qualified paths with filters, compact/full modes, and pagination so assistants narrow candidates before reading files. Optional local semantic search (fastembed-rs) is separately configurable and downloads local model weights on first enable.

deterministic lexicalcompact & fullpaginationoptional semantic

Typed question planning & impact

Read-only planning maps supported codebase questions to bounded relationship queries (find_callers, symbol_context, get_subgraph, pre_edit_impact) and asks for clarification when a question falls outside supported graph actions.

Storage lifecycle & diagnostics

Inspect and reclaim multi-branch disk usage with dry-run-first gcx storage list / prune / gc / compact. Verify hooks, store health, and editor wiring via gcx doctor and gcx status --json.

Explorer & graph export

gcx viz renders the local graph with Cosmograph WebGL; gcx export emits Mermaid, DOT, JSON, HTML, SVG, and GraphML. Opt-in local diagnostic MCP call metadata is bounded to 2 MiB and excludes raw arguments and contents (usage insights and an Activity UI remain future work).

Install · v0.8.0

Five ways in. All of them ship a binary.

Pre-built binaries cover macOS (arm64, x86_64) and Linux (x86_64, arm64). On Windows, use WSL2. Run gcx init in a repo to index, install git hooks, and wire in your AI assistant (or gcx init --editor none for CLI-only setup). 

# macOS or Linux (v0.8.0)
brew install bharath03-a/tap/gitcortex

# Index, install git hooks, and interactively wire in your AI assistant
gcx init
gcx doctor

Installs the pre-built gcx binary. No Rust, Python, or Node.js runtime required.

# Python 3.8+ wheel (bundles pre-built v0.8.0 binary)
pip install gitcortex==0.8.0

# Or isolated
pipx install gitcortex==0.8.0
uv tool install gitcortex==0.8.0

gcx init && gcx doctor

Wheels bundle pre-built binaries for macOS arm64/x86_64 and Linux x86_64/arm64. No Rust toolchain required.

# Build from crates.io (Rust 1.80+)
cargo install gitcortex --version 0.8.0 --locked

gcx init && gcx doctor

KuzuDB builds from source under Cargo, so the first compilation takes roughly five minutes.

# Global install (bundles pre-built v0.8.0 binary)
npm install -g gitcortex@0.8.0

# Or pnpm / bun
pnpm add -g gitcortex@0.8.0
bun add -g gitcortex@0.8.0

gcx init && gcx doctor

Bundles the same pre-built binaries as the Python wheel.

# macOS arm64 (v0.8.0)
curl -LO https://github.com/bharath03-a/GitCortex/releases/download/v0.8.0/gitcortex-aarch64-apple-darwin.tar.xz
tar -xf gitcortex-aarch64-apple-darwin.tar.xz
sudo mv gcx /usr/local/bin/

# Linux x86_64 (v0.8.0)
curl -LO https://github.com/bharath03-a/GitCortex/releases/download/v0.8.0/gitcortex-x86_64-unknown-linux-gnu.tar.xz
tar -xf gitcortex-x86_64-unknown-linux-gnu.tar.xz
sudo mv gcx /usr/local/bin/

All platform archives and checksums are published on the releases page.

Upgrading from v0.7.x (Graph Schema v15): v0.8.0 advances the embedded graph schema to v15 for fast incremental reconciliation and storage lifecycle metadata. After upgrading the binary, rebuild existing local indexes cleanly with gcx clean && gcx init (or run gcx init when prompted on schema mismatch), then verify with gcx doctor.
MCP server & CLI

Structured envelopes, not a chat box.

Add gcx serve to your MCP configuration (or call gcx query ... directly from CLI agents). Every response uses an object envelope carrying explicit readiness and coverage metadata.

  • lookup_symbol(name)Every definition matching a symbol name across the active branch
  • find_callers(name, depth?)Cross-file diversified callers with file:line evidence
  • symbol_context(name)360° view: definition, callers, callees, and type usages
  • get_subgraph(name, depth)Bounded neighbourhood: callers, callees, implementations
  • search_code(query)Progressive lexical search with filters, compact/full modes, and pagination
  • pre_edit_impact(name)Production-first transitive caller impact with separate test counts
  • branch_diff(from, to)Structural symbol & edge difference between two indexed branches
  • find_god_nodes / find_clustersIn-degree hub detection and deterministic label-propagation clusters

.mcp.json (project root)

{
  "mcpServers": {
    "gitcortex": {
      "command": "gcx",
      "args": ["serve"],
      "env": {}
    }
  }
}
