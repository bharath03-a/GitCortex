# GitCortex Usability Implementation Plan

**Goal:** Make the first useful, verifiable graph answer easy to reach; make setup, recovery, and unavailable evidence actionable; make `gcx viz` readable without magnification.

**Architecture:** Keep the existing CLI → readiness → GraphStore boundaries. Reuse the MCP `index` envelope, the existing repository resolver, and Plan 04 D3's shared exit helper. Improve presentation and integration contracts rather than introducing another indexer, query protocol, configuration file, or daemon. Tokenize typography once, apply it to the current React UI and Cosmograph labels, and pin the result with visual and computed-style checks.

**Tech Stack:** Rust/clap/serde_json, existing `IncrementalIndexer` and KuzuDB behind `GraphStore`, React/TypeScript/Tailwind 4/Vite, Space Grotesk + IBM Plex Mono, Vitest, Python unittest, Playwright for future visual acceptance only.

**Spec:** [Release program](2026-11-05-00-release-program.md), [delivery Stack F](2026-11-05-07-delivery-orchestration.md); maintainer request, 2026-11-05, “improve fonts in the UI”; supplied web-mode screenshot `9d472a03-eac2-40a0-8892-629f1aef0e85-981f289f-6483-4fbb-b313-6112151dc74f.png`; command/source audit below. Read alongside Plans 01–05; their ownership is preserved below.

## Global Constraints

- One named task F0–F9b (including lettered splits) = one stacked-PR layer, approximately ≤400 changed lines excluding lockfiles and visual baselines. Split before dispatch if estimates exceed that; record new SHA edges in Plan 07. This revision edits only Plan 06 and Plan 07’s Stack F rows/dependencies. Everything ships through `gh stack`; independent stacks are allowed. No implementation, commits, pushes, or subagents were run for authoring.
- No `.unwrap()` or `.expect()` added to library code. Core stays pure; indexer/store stay synchronous. No new tokio usage outside `gitcortex-mcp`; preserve existing CLI/viz server boundaries without an async migration in Stack F.
- Repository configuration is `.gitcortex/ignore` only. Generated guides/context and editor integration files are artifacts, not new configuration formats. Do not add `.gitcortex/config.toml` or automatically edit `.gitignore`, commit files, or suppress all generated Markdown from readiness.
- Every audit/test gcx subprocess has `GCX_STORE_PATH` pointing to an isolated temporary root; subprocess HOME is isolated for editor tests. Never use the maintainer's store, hooks, or editor settings. Tests set the store env before process launch because data-root selection is process-global.
- Every MCP response continues to carry readiness under **`index`**, never `scope`. Use `gitcortex_mcp::mcp::readiness::{inspect, IndexReadiness}`; keep `index.state`, `index.branch`, `index.working_tree_verified`, and `index.next_action`. Unknown or empty evidence never establishes safety.
- Plan 02 owns lifecycle correctness, tree indexing (`IncrementalIndexer`, not `Indexer`), daemon recovery, and source-verification semantics. F explains those states; it does not bypass them or invent a second readiness function.
- Plan 04 T3/D3 owns `crates/gitcortex-cli/src/exit.rs`: `CliExit` and `exit_code`; Plan 05 consumes it too. F1 consumes the merged API rather than declaring another exit enum. Invalid seed/ref = 2; not ready = 3; other errors = 1; clap remains 2. Valid but unindexed branch is not a bad ref.
- Plan 04 owns graph export readiness, Mermaid, static bundles, legacy-format compatibility, and export documentation. Plan 05 owns impact behavior and managed CI workflow migration/deinit. Plan 03 owns store identity, pruning, compaction, and migration. Do not reproduce these features here.
- Keep both font families: Space Grotesk provides the existing product identity and readable proportional prose; IBM Plex Mono makes code identifiers and paths distinguishable. Do not add a third family or remote font requests. Metadata, counters, controls, section headings, and status prose use sans; code identifiers, paths, and literal command examples use mono. Keyboard keycaps can use sans.
- Future Playwright design, execution, debugging, and screenshots belong to `gpt-6-luna` under the user preference. This authoring task explicitly forbids subagents, so no Playwright was executed here. F8's implementation must route that work to Luna and record the result; do not imply baseline screenshots have already passed.
