Head-to-head · measured, not estimated

GitCortex vs Graphify, on the same questions.

Graphify is a real, fast-growing open-source project (106k+ GitHub stars, 4.5 months old) that does the same core thing GitCortex does: turn a codebase into a graph an AI agent can query instead of grepping. This page runs both against the same 5 pinned repos, the same 15 questions, and the same client (Claude Code), and reports what actually happened — including where Graphify won and where our own methodology needed correcting along the way.

The numbers

15 tasks — deep blast-radius, cross-file architecture, refactor-safety — across ripgrep, requests, hono, cobra, and gson. Both tools code-only (Graphify also does docs/SQL/configs; not tested here — see the honesty section below).

GitCortex used 1.32× fewer tokens and scored 60% higher on answer quality across the same suite. Quality is the share of independently-verified required evidence (file paths / symbols confirmed against the actual source, not against either tool's own output) that appeared in the agent's final answer.

Why the gap: reliability, not raw capability

Graphify's underlying extraction is competent — on tasks where it resolved the right symbol, its answers were as good as GitCortex's. The gap comes from two consistent, measured patterns:

Finding 1 — one call vs several, every single task

Claude Code called GitCortex's MCP tool exactly once, on all 15 of 15 tasks — it always got a structured, sufficient answer on the first call. Against Graphify's CLI, the same model needed 2 to 5 attempts on every single task (average 2.7), and on 6 of 15 fell back to raw file exploration in addition to the graph queries. That's not one flaky run — it's a 100% consistent pattern across the whole suite, and it's the direct cause of Graphify's higher token cost.

Finding 2 — a verified ambiguity bug

Asked about Searcher::line_number() in ripgrep (a config getter), Graphify's affected command silently traced Sunk::line_number() instead — an unrelated method that happens to share a short name, called 76 times elsewhere in the codebase. The answer was confident, well-formatted, and about the wrong symbol entirely.

This is the same bug class we found and fixed in our own symbol_context tool while preparing this release (see CHANGELOG) — short-name ambiguity is a real, easy-to-hit failure mode for any code graph tool, and it's worth checking for regardless of which tool you use.

Where Graphify is ahead of us

Scope: Graphify indexes docs, SQL schemas, Terraform/config files, and PDFs/images into the same graph, via LLM-assisted semantic extraction. GitCortex indexes code only. This comparison is code-only by design — we didn't test the surface where Graphify does strictly more than we do, because it would be a guaranteed, uninteresting loss for us to record.

Language coverage: Graphify supports roughly 40 languages via tree-sitter; GitCortex supports 5 today (Rust, Python, TypeScript, Go, Java).

Scale and maturity of the project: Graphify has 106,000+ GitHub stars and 10,000+ forks after 4.5 months. GitCortex is a much smaller, newer project. Community size isn't a benchmark result, but it's real context for anyone reading this page.

Methodology

  1. Five real open-source repos, pinned to an exact commit: ripgrep, requests, hono, cobra, gson.
  2. Same 15 questions for both tools (deep blast-radius, cross-file architecture, refactor-safety), same client (Claude Code, Haiku), same required-evidence contracts.
  3. GitCortex accessed via its MCP tool (mcp__gcx); Graphify accessed via its CLI (graphify affected / graphify explain, code-only mode, --code-only) since it has no MCP integration wired into this harness yet.
  4. Quality is the fraction of independently-verified required evidence present in the final answer, corrected for citation-format (class/method name vs. full path) after manual review of every non-1.0 result on both sides — the same correction applied equally to both tools.
  5. We hit two real problems getting a clean run and are disclosing both: an early version of this script under-restricted Graphify's sandbox (it could fall back to raw grep/find), and a later fix over-restricted it (Claude Code disabled Bash entirely when a scoped allow and a bare disallow were combined). The final run removed the conflicting rule and used --dangerously-skip-permissions in this sandboxed, repos-only context to get deterministic tool access for both arms.
  6. Full harness, task definitions, and raw per-task logs: tools/agent-bench/ in the repo, including graphify_compare.py.
